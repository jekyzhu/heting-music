# 合听 Android 0.8.0 智能音效

只提供安卓手机版，适用于 ARM64 手机。开发仓库：jekyzhu/heting-music；
按用户要求，最终源码包同时备份到 jekyzhu/-。

## 使用

打开侧边栏“智能音效”，开启音效。可选择原声、摇滚、民谣、流行、古典、电子预设，
也可拖动五个频率滑杆。手动调节自动保存为“我的音效”，退出自动模式，切歌和重启后保留。

开启“根据歌曲风格自动切换”后，优先使用歌曲明确提供的风格标签；没有标签时，
在本机分析合听实际解码的音频。连续三个窗口的候选风格一致且达到置信度及领先幅度门槛后，
平滑切换音效。一般需要约 10–40 秒有效播放；识别不确定时保持原声，可随时手动选择。

使用的是 Google YAMNet 通用音频事件模型，涵盖 Rock music、Folk music 等类别。
它提供风格线索，不能保证每首歌都分类正确；模型分数不等于实际准确率。每首歌达到稳定
结果后停止分析，最多尝试十个窗口；切歌、手动模式和音效关闭会清除旧任务，避免旧结果覆盖。
不使用麦克风，不录音，不上传音频。模型随安装包提供，安装后识别无需单独联网。

原生均衡器按设备实际频段插值，曲线约 400 毫秒过渡。为减少削波预留正增益余量，
开启后整体响度可能稍低。预设是听感起点，需按耳机和喜好调整。设备不支持音效时继续原播放。

## 构建与验证

需要 Node 18+、JDK 17、Go 1.25.1、Android SDK 35、NDK 26.1.10909125。
在 android-app 中安装依赖 npm ci --legacy-peer-deps --ignore-scripts，执行
scripts/build-account-engine.sh 构建内置账号库；Gradle preBuild 会下载并校验 YAMNet。
运行类型检查、Jest、Android unit tests 和 assembleRelease，得到独立可安装 APK。

GitHub Actions 会打包 APK、完整源码 ZIP、说明及 SHA-256 校验文件。
源码 ZIP 包含模型；也可用源码内脚本从固定官方地址重建模型文件。
当前 APK 使用项目现有个人测试签名；能否覆盖旧安装包须以实际签名检查为准。
正式分发应配置自己的签名并遵守上游许可。

验证包括类型检查、账号/歌单及音效规则测试、PCM 原样通过测试、识别投票/低置信度测试、
安卓原生编译及 APK 构建。**真实音乐风格准确率、不同手机/耳机/蓝牙、后台耗电和听感仍需真机验收**。
这些不能仅凭编译或单元测试通过就视为已经验证。
