# 合听 Android 0.8.1 播放修复

用户反馈：所有歌曲点击播放后，图标反复闪烁，没有声音；关闭智能音效后仍然发生。

代码中确认的问题与修改：

- 根因：音效分析处理器没有忽略空音频输入。ExoPlayer 会在真实播放管线排空时传入共享空缓冲区；处理器尚未分配输出缓冲区时，输入输出为同一对象，`ByteBuffer.put` 因自拷贝抛出 `IllegalArgumentException`。这个路径先于分析开关判断执行，因此关闭音效也无法避免。已提前返回空输入，并增加对应原生回归测试，保留已有待输出音频。
- 旧播放队列包含 `musicfree://proposed-audio` 和 `musicfree://fake-audio`，这两个地址不是音频资源。移除占位资源，只把解析后的真实音源交给原生播放器；使用原生队列结束事件推进下一首和单曲循环。
- 旧错误处理每 500 毫秒自动切下一首，没有失败上限。现在失败后暂停，提示错误代码；重复错误只提示一次，避免整张歌单无限跳转。
- 播放失败后点击重试，重新解析音源，不复用失效地址。
- 暂停或切歌使旧异步解析失效，避免旧请求稍后恢复播放。
- 启动恢复任务失效后不得覆盖新播放请求；重新启动时不复用旧的内置服务端口和授权头。
- 修复备用音质音源被空的顶层 URL 覆盖的问题，保留授权请求头。

验证：新增播放器流程回归测试，以及 Android API 29 和 API 36 模拟器上的实际解码/AudioTrack 测试：本地 WAV、携带授权头的 HTTP 流，分别覆盖分析开关、进度前进、暂停、继续、正常结束。后者必须由 CI 执行通过后才打包 APK。

复现证据：修复前 Android API 29 模拟器四项实际播放测试全部失败，原生日志均指向 `HetingAnalysisProcessor.queueInput` 的 `ByteBuffer.put` 自拷贝异常。

边界：没有连接用户小米 17 Ultra，也没有读取其账号的播放日志。上述根因已在模拟器复现并定位，仍需在用户手机上复测。若仍失败，请记录新版显示的错误代码；不要发送平台密码、Cookie 或私密播放地址。

安装：同一应用包名与签名，版本号提升为 0.8.1（400015），覆盖安装即可。先保留旧版及其登录数据，避免卸载造成数据丢失。
